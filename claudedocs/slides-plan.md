# 登壇用スライドとトークスクリプトの計画

作成日: 2026-11-17 ／ 想定: 登壇8分、1スライド1メッセージ、枚数は多くてよい

## 1. 成果物と置き場所

```text
TAS_SUT/
├── slides/
│   └── deck.md                 # 唯一の原稿。1スライド＝1ブロック（メッセージ、図、補足、トーク）
├── scripts/
│   ├── build_slides.py         # deck.md → _site/slides/index.html（スライド）と _site/slides/script.html（トークスクリプト）
│   └── check_slides.py         # スライド規約の機械検査（下記 §3）
├── site-src/slides.css         # スライド専用スタイル（記事のCSSとは分離、配色は共通）
└── assets/                     # 図は記事と共有。スライド専用の図も同じ draw_figures.py で生成
```

- 公開URLは `…/test-automation-cost-structure/slides/`。記事の目次ドロワー下部とREADMEからリンクする。
- スライドはHTML。縦方向の scroll-snap で1画面1スライド。矢印キーでは scroll-snap がページ送りにならなかったため、キー操作（矢印・PageUp/Down・スペース・Home/End）のための最小限のインラインスクリプトだけを埋め込む（外部通信・ライブラリなし）。`@media print` で1スライド1ページのPDFにできる。
- トークスクリプトは deck.md の各スライドの `notes` から生成する。スライド番号、見出し、目安時間、原稿の順に並べた1ページのHTML。Markdownのまま読む場合は deck.md を開けばよい。

## 2. 統一ルール（デザイン）

| 要素 | ルール |
| --- | --- |
| 画面 | 16:9。論理サイズ 1600×900 を基準に `vw`/`vh` で拡縮。左右の余白 80px |
| ヘッダー | 左上：章ラベル（`01 問題` のように番号＋2〜4字。章ごとに固定）。右上：`n / N` のページ番号（CSSカウンター） |
| メインライン | 上段にメッセージ見出し1文（全角28字以内、結論形。図の題名と同じでもよい）。中段に図1点（`assets/*.svg`、最大幅 1200px・最大高 560px）または箇条書き最大3項目（1項目全角24字以内）。図と箇条書きは併用しない |
| 下段 | メッセージライン（必須、1〜2文・全角64字以内）。見出しの主題に対する結論文で、スライド単体で読んで理解できるようにする。左に線を付けた帯で表示。さらに任意で補足1行（40字以内、MUTED色） |
| フッター | 左下：記事題名の短縮「生成と検証から考えるテスト自動化」＋日付。右下：公開URL。全スライド共通 |
| 配色 | 図と同じ役割色（NEUTRAL / PRIMARY / AI / POSITIVE / ATTENTION / INK）。背景は BG。強調は1スライドに1箇所（ATTENTION）まで |
| 文字 | 見出し 44px 太字 INK、箇条書き 28px T1、補足 22px MUTED、ヘッダー・フッター 18px MUTED。フォントは記事と同じ system sans |
| 特殊スライド | 表紙（題名・肩書き・日付・URL）、章扉（章番号と章名のみ、PRIMARYの帯）、まとめ（結論3行）。章扉は番号を振るが本文スライドと同じヘッダー・フッターを持つ |
| 図の扱い | 記事の図をそのまま使う。スライド専用に新規に描く図も draw_figures.py に追加し、同じ検査（配色・コントラスト・はみ出し・キャプション）を通す。図の題名がメッセージと重複する場合は、スライド側では見出しを言い換える |

## 3. 機械検査（check_slides.py）

- 各スライドに見出しがあり、全角28字以内。
- 図は1点以内、箇条書きは3項目以内で、両方を持たない。図の参照先が `assets/` に実在する。
- 表紙以外にメッセージラインがあり、64字以内。
- 補足行は40字以内。
- 各スライドに `notes`（トーク原稿）があり、1スライドの原稿は全角40〜160字。
- 原稿の合計は 2,000〜2,400字（日本語の登壇は約300字/分。8分で2,400字が上限。表紙・章扉は10字以上160字以内）。
- `<script>` を含まない。配色は図と同じパレットのみ。

## 5. 新規に描く図（2点、記事にも載せる）

- `07b-ai-test-environment-connection`：Claude Code などのAIエージェントを中心に、左へ「CI」、右へ「テスト環境」（ブラウザ／対象環境＝打鍵、DB・バッチ＝結果確認、ミドルウェア経由）の2本の接続。下に「これらの接続の構築・保守＝TASの領域」。§7 の追記段落の直後に置く。
- `08f-spa-vs-jsp-test-layers`：左 SPA（単体＝Vitest、コンポーネント＝Storybook、フロント結合＝Playwright、E2Eは主要シナリオに絞る。Testing Trophy）、右 JSP（サーバーでHTMLを組み立て、単体で描画できない → 打鍵によるビッグバン型E2E → だからE2E自動化が方策）。§8.4 の末尾に置く。

## 6. 手順

1. `site-src/slides.css`、`scripts/build_slides.py`、`scripts/check_slides.py` を作り、空のデッキで骨格（ヘッダー・フッター・章扉・番号）を確認する。
2. 新規図2点を draw_figures.py に追加し、記事にも挿入する（図版30点）。
3. `slides/deck.md` に本編24枚＋予備6枚を書く。各スライドに notes（原稿）を付け、合計2,400字以内に収める。
4. ビルドして、ブラウザで16:9表示とPDF印刷を確認する。原稿を音読して8分以内かを確認する（目安 300字/分）。
5. pages.yml に build_slides / check_slides を加え、README に「登壇資料」の節を足す。
