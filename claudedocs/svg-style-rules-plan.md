# SVG作成ルールの改善計画（配色の意味づけ・統一・視認性）

作成日: 2026-11-17 ／ 対象: `assets/*.svg`（11点）と `scripts/draw_figures.py`、`scripts/check_figures.py`

## 1. 現状の問題（棚卸し結果）

| 観点 | 現状 | 問題 |
| --- | --- | --- |
| 色の意味 | 箱の塗りは `FILLS[i % 5]` で位置順に5色を巡回（02・03・08） | 色が意味を持たず、読者は「色の違い＝何かの違い」と誤読する |
| 色数 | 全体17色。1図あたり塗り4〜6種＋線色2〜4種 | 多すぎて強調が埋もれる。03は年表タイルが5色 |
| 強調色の重複 | 朱（ACCENT）を「負担・残る課題」「結論の強調」「遷移の矢印」に混用 | 何が注意点で何が結論か区別できない |
| 文字の視認性 | 緑文字 on 緑地 2.66、朱文字 on 橙地 3.50、緑文字 on 地色 3.08 | WCAG AA（小さい文字 4.5）未満。縮小表示（約10〜11px）ではさらに読みにくい |
| 線の意味 | 実線・破線・太さの使い分けが図ごとに異なる | 「流れ」「遷移」「注釈」の区別が付かない |
| 図ごとの焦点 | 1図に強調が複数ある（例：10は領域2つ＋矢印＋ラベルが全部色付き） | 最初に見るべき箇所が定まらない |

## 2. 改善ルール（案）

### 2.1 色の役割を5つに固定する

| 役割 | 意味 | 塗り（地） | 文字・線 | 使う場面 |
| --- | --- | --- | --- | --- |
| NEUTRAL | 区別を付けない基本要素、従来・自社で担うもの | `#eef3f1` | 文字 T1/T2、線 LINE `#607a91` | 工程・年表タイル・条件・鎖の既定色 |
| PRIMARY | 主題のシステム・領域・選択肢 | `#e1edf8` | 文字 T1/T2、見出し PRI_TEXT `#2b5f9e` | SUT/TAS、第一層/第二層、SaaS/Playwright領域 |
| POSITIVE | 削減・移転・成功（負担が減る側） | `#e0f0e9` | POS_TEXT `#2f6b45`、線 `#5aa06f` | 削減されるもの、提供者が担う、初回成功 |
| ATTENTION | 残る負担・課題・注意・ボトルネック（**1図に1系統**） | `#f7e9d4` | ATT_TEXT `#9c3f2a`、線 `#c0604a` | 検証の帯、保守要因、残る判断、失敗事象、注意書き |
| INK | 結論・題名・判断の強調 | 塗りなし | `#18324b`（太字） | 図の結論文、判断の箱の枠 |

- 紫（PURPLE / F3）とピンク（F4）は廃止する。AI支援は PRIMARY、自社負担は NEUTRAL で表す。
- 1図で使う色相は最大3（NEUTRAL は色相に数えない）。地の塗りは最大4種。
- 「結論」は色ではなく INK の太字で示し、ATTENTION は「残るもの・注意」だけに使う。

### 2.2 文字と視認性

- 文字色と地色のコントラスト比を **4.5以上** にする（全文字）。候補パレットでは最小が MUTED on WATER 4.26 のため、水面下の注記は地色の上に置くか、MUTED を `#55646d` に暗くする。
- 最小14px・注記16pxは維持。色付き文字は太字のみ（細字の色付き文字は使わない）。
- 色だけで状態を伝えない。05のように色が状態を表す図は、必ず凡例と文字ラベルを併記する。

### 2.3 線と形

- 実線＝実際の流れ・因果、破線＝時間的な遷移や方針、細い実線（2px）＝注釈の引き出し線。
- 枠線は既定1px。ATTENTION の強調枠は2px。3pxは1図に1箇所まで（最初に見るべき箇所）。
- 角丸は箱12px、ピル（丸長）は高さの半分。矢印の矢頭は共通関数で統一。

### 2.4 図ごとの焦点

- 各図で「最初に見るべき1箇所」を決め、そこだけ ATTENTION または3px枠を使う。
- 題名は結論文（現状維持）。注記は補足と前提（概念的な比率など）に限定する。

## 4. 実装・検証の変更

1. `scripts/draw_figures.py`：色定数を役割名（`NEUTRAL / PRIMARY / POSITIVE / ATTENTION` と各文字色）に置き換え、`FILLS[i % 5]` の巡回を全廃する。`box()` などの既定塗りを NEUTRAL にする。
2. `scripts/check_figures.py` に次を追加する。
   - パレット検査：許可色（役割表の色）以外の色が出たら失敗。
   - 色数検査：1図の地の塗りが4種を超えたら失敗。
   - コントラスト検査：各 `<text>` の文字色と、その文字を内包する最後の `<rect>`（なければ背景）の塗りの比が4.5未満なら失敗。
3. 11点を再生成し、PNG化と本文幅（720px）のブラウザ表示で目視確認する。
4. README の編集ルールに配色ルール（役割・色数上限・コントラスト4.5）を追記する。
5. 計画どおりなら、§1の文削除・04の分割と合わせて1コミットにまとめる（push は指示があるまで行わない）。

## 5. 決定事項（2026-11-17）

- 紫は「AI支援」の役割色として残す（AI `#e9e4f5` / 線 `#8a6cc1` / 文字 `#6a4ea6`）。色相は最大4（PRIMARY・AI・POSITIVE・ATTENTION）、地の塗りは1図4種以内のまま。
- 10 の2領域は、ノーコード型SaaS を PRIMARY、Playwright＋AIエージェント を AI で塗り分ける。
- MUTED を `#55646d` に暗くし、水面（WATER）上の注記でも4.5以上を満たす。
- 実装済み：`scripts/draw_figures.py` を役割名の配色に書き換え、`scripts/check_figures.py` にパレット・塗り色数・コントラストの検査を追加。全11点が検査を通過。

## 6. 当初の確認事項（決定済み）

- 紫（AI支援）を廃止して PRIMARY に寄せる案でよいか。AI支援を独立した色で残したい場合は、PRIMARY を「構造」、紫を「AI支援」に分けて色相4までとする。
- 10 の2領域を同色（PRIMARY）にする案でよいか。見分けやすさを優先するなら SaaS を PRIMARY、Playwright を NEUTRAL にする。

## 7. キャプションのルール（2026-11-17 追加）

- 問題：alt にアクセシビリティ向けの長い説明文を入れていたため、ビルド後のキャプションが2〜3行になり、図の題名と重複していた。
- ルール：キャプション（alt ＝ aria-label）は図の主題を表す名詞句、全角30字以内、要素の列挙や「〜を示す図」の結びは使わない。図の中の題名（結論文）と重複させない。詳しい説明は `<desc>` に移し、`aria-describedby` で結ぶ。
- 検査：`draw_figures.svg()` が30字超で例外、`check_figures.py` が aria-label の長さと `<desc>` の有無、`check_html.py` が alt の長さを検査する。

## 8. 参考文献の形式（2026-11-17 追加）

- medium-specificity に合わせ、本文の引用は pandoc 脚注 `[^key]`（キーは出典を表す英語スラッグ）、文末の「## 参考文献・注記」に `[^key]: 著者, *題名*（年）。補足。URL` の形で定義する。pandoc が `fn`/`fnref` の往復リンクを生成し、CSS の `.footnotes` 系ルールで体裁を整える。
- 同じ出典を2箇所から参照しないこと（pandoc の脚注キーは1回しか参照できない）。
